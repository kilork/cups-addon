# Agent Context — CUPS Print Server Addon

## Project Overview

Home Assistant addon providing a CUPS print server with USB printer support, REST API, and MQTT auto-discovery. Forked from `arest/cups-addon`.

## Key Decisions

### Samsung M2020 Printer Support
- **SpliX built from git master** — Alpine package (2.0.0) is too old. M2020 support added in Oct 2025 (commit `206e283`).
- **USB quirks file** (`samsung-m2020.usb-quirks`) — Contains `no-reattach unidir` for USB ID `0x04e8:0x3321`. Prevents `Device reset failed` errors.
- **PPD file** — Generated by Splix's `compile.sh` from `samsung.drv.in`. Must have `*QPDL SpecialBandWidth: True` (no quotes).
- **CUPS runtime PPD mismatch** — The runtime PPD at `/share/cups/config/ppd/Samsung_M2020_Series.ppd` is a COPY made by CUPS when the printer is added. Editing the model PPD alone won't update it — the printer must be re-added.

### Rust cups-api Binary
- Built with axum, serde, tokio, rumqttc, reqwest.
- Multi-stage Docker build: `rust:alpine` → final image.
- Single static musl binary at `/opt/cups-api/cups-api` (~5MB).
- **PID 1** — the binary is the container's main process.
- **Spawns cupsd** as a `tokio::process::Child` with `kill_on_drop(true)`.
- **tokio::select!** serves HTTP requests until cupsd exits, then shuts down.
- **Setup** — `setup()` function at startup handles:
  - Directory creation (`/share/cups/{cache,logs,state,config,ppd,ssl}`)
  - `cupsd.conf` generation (embedded as a const string)
  - Legacy `/data/cups → /share/cups` migration
  - `/etc/cups` symlink to `/share/cups/config`
  - User-supplied `.deb` driver extraction via `dpkg -x`
- Reads config from env vars (`CUPS_API_PORT`, `MQTT_HOST`, etc.).
- Reads addon options from `/data/options.json` for `api_port` and `printer_driver_deb`.

### MQTT Auto-Discovery
- Requires `services: ["mqtt:want"]` in `config.yaml` to grant supervisor API access.
- Queries `http://supervisor/services/mqtt` with `Authorization: Bearer $SUPERVISOR_TOKEN`.
- Falls back to manual env vars (`MQTT_HOST`, `MQTT_PORT`, `MQTT_USERNAME`, `MQTT_PASSWORD`) if set.
- Publishes to `homeassistant/sensor/cups_printer/{config,state,attributes}`.

### CI/CD
- GitHub Actions builder runs on push to `main`.
- `MONITORED_FILES` in `builder.yaml` controls which file changes trigger a build: `config.json config.yaml config.yml Dockerfile rootfs cups-api`.
- Version is read from `cups/config.yaml`, not git tags. Both must stay in sync.
- The image tag matches the version string (e.g. `1.7.5` → `ghcr.io/kilork/cups-addon:1.7.5`).

## Development Workflow

1. Edit code → `git add -A && git commit -m "message"`
2. `git tag -a v<version> -m "message"`
3. `git push origin main v<version>`
4. Wait for CI build (≈5 min)
5. `gh release create v<version> ...`
6. HA Supervisor picks up the new tag automatically

### Architecture notes

- cups-api is PID 1, spawns cupsd as child via `tokio::process::Command`
- ctrl+c / SIGTERM → forwarded to cupsd via `kill_on_drop(true)`
- If cupsd exits, cups-api shuts down (tokio::select! returns)
- Boot script is minimal: `exec /opt/cups-api/cups-api` — cups-api handles all setup in `setup()`

## Useful Commands

```bash
# SSH to HA host
ssh ha.lan

# Inside the container
sudo docker exec addon_23db2e62_cups <command>

# Check CUPS logs
sudo docker exec addon_23db2e62_cups tail -30 /var/log/cups/error_log

# Test API
curl http://<ha-ip>:8000/api/status | jq

# Pull new image manually
sudo docker pull ghcr.io/kilork/cups-addon:<version>

# Force supervisor update
# HA → Settings → Apps → CUPS Print Server → ⋮ → Check for updates
```
